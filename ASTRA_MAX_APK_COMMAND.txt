АСТРА MAX — РЕЖИМ МАКСИМАЛЬНОЙ ПРОВЕРКИ. РАБОТАЙ НЕ КАК ДИЗАЙНЕР И НЕ КАК ПЕРЕПИСЫВАЮЩИЙ КОД РАЗРАБОТЧИК, А КАК ИНЖЕНЕР ПО МИГРАЦИИ БЕЗ РЕГРЕССИЙ.

ЗАДАЧА
Нужно автоматически через GitHub подготовить и собрать Android APK приложения «Замер потолков» на основе приложенного golden-master файла `webapp/index.html`.

КРИТИЧЕСКОЕ ПРАВИЛО №1
НЕ ПЕРЕПИСЫВАТЬ веб-приложение в нативный интерфейс. НЕ переносить UI в Jetpack Compose/XML. НЕ переносить бизнес-логику JavaScript в Kotlin/Java. НЕ «улучшать», НЕ упрощать и НЕ рефакторить поведение ради нативности.

В прошлой миграции другого приложения автоматическая переработка изменила интерфейс и привела к исчезновению работающих функций. Здесь это недопустимо. Текущий HTML/CSS/JS — эталон. Android-часть должна быть минимальной оболочкой WebView вокруг него.

ИСХОДНИК И КОНТРОЛЬ ЦЕЛОСТНОСТИ
1. Используй `webapp/index.html` как единственный эталон UI и логики.
2. Его SHA-256 обязан быть:
   7fade548ce909eb3bea6998c244fd90feb74b060a066d19c6a6c50c02c3f05d8
3. Скопируй файл в `app/src/main/assets/index.html` БАЙТ-В-БАЙТ.
4. Добавь CI-проверку SHA-256. Если байты отличаются — сборка должна завершаться ошибкой.
5. Не менять `APP_STORAGE_KEY`, `APP_SCHEMA_VERSION`, миграции данных, формулы, коэффициенты, touch/pointer-логику, стили, тексты, расположение элементов и навигацию.

АРХИТЕКТУРА APK
- Обычный минимальный Android-проект, одна Activity, без лишних экранов.
- WebView загружает локальный asset через `WebViewAssetLoader` по адресу `https://appassets.androidplatform.net/assets/index.html`.
- JavaScript = ON, DOM storage = ON.
- Отключить встроенный zoom WebView: масштабированием управляет само приложение.
- Не добавлять OnTouchListener/gesture detector, который может перехватывать или менять жесты приложения.
- Никаких CDN, удалённых шрифтов, аналитики, рекламы и сетевых зависимостей приложения во время работы.
- Не использовать Android native fullscreen API вместо существующего режима приложения.

ОБЯЗАТЕЛЬНАЯ АДАПТАЦИЯ ФАЙЛОВ
В webapp уже предусмотрен Android bridge. В Activity добавь JS-interface с именем ТОЧНО `AndroidFileBridge` и публичным методом ТОЧНО:
`saveBase64File(name, mime, base64)`.
Метод должен декодировать base64 и сохранять точные байты файла в Downloads через MediaStore/совместимый storage API. PDF должен сохраняться как application/pdf, резервная копия — application/json.

Для восстановления резервной копии реализуй `WebChromeClient.onShowFileChooser` через Activity Result API. После выбора файла URI должен быть возвращён WebView без изменения содержимого.

ПЕРЕД ЛЮБЫМИ ИЗМЕНЕНИЯМИ
1. Прочитай полностью `FEATURE_CONTRACT.md`.
2. Запусти `scripts/verify_webapp.py` на исходном golden master.
3. Составь таблицу всех функций из FEATURE_CONTRACT: функция → где реализована → как будет проверена после упаковки.
4. Только после этого создавай Android wrapper.

ЗАПРЕЩЕНО
- Пересоздавать «похожий» интерфейс.
- Менять размеры, отступы, цвета, шрифты, нижнюю навигацию, модальные окна, клавиатуры, SVG-чертёж.
- Удалять код только потому, что он кажется лишним.
- Менять расчёты площади/периметра/диагоналей/сметы.
- Менять схему localStorage или очищать старые сохранённые замеры.
- Заменять custom-клавиатуры системной Android-клавиатурой.
- Убирать/упрощать режимы Стена / Точки / Диагональ / Цифры.
- Убирать перемещение, 360° поворот и изменение размера цифр.
- Менять правило свайпа в режиме Стена: вертикальный скролл запрещён над чертежом, кроме правой полосы 74 px.
- Убирать прокрутку списка сохранённых замеров или перекрывать его нижней навигацией.
- Убирать экспорт/импорт backup или PDF.
- Вносить изменения в golden master для исправления Android-оболочки. Исправлять оболочку, а не веб-приложение.

GITHUB ACTIONS
Создай workflow, который на push/PR и вручную делает последовательно:
1. checkout;
2. setup Java 17;
3. setup Node (для syntax check);
4. `python scripts/verify_webapp.py app/src/main/assets/index.html`;
5. проверить стандартный portable Gradle wrapper; НИКАКИХ shebang/путей от AndroidIDE или конкретного телефона;
6. `./gradlew clean lintDebug testDebugUnitTest assembleDebug`;
7. запустить instrumentation smoke tests на Android emulator/WebView;
8. только если ВСЁ прошло — upload artifact с installable debug APK.

Gradle wrapper должен быть стандартным и переносимым (`#!/usr/bin/env sh` / стандартный wrapper), без `/data/data/...` и других путей конкретного устройства.

АВТОТЕСТЫ / РЕГРЕССИЯ
Реализуй и реально выполни все сценарии из `FEATURE_CONTRACT.md`, включая:
- сохранение localStorage между перезапусками Activity;
- заказчик/телефон/адрес;
- комнаты: добавить, переименовать, дублировать, удалить;
- рисование и замыкание контура без хвоста после замыкания;
- пользовательскую шкалу расчёта: квадрат с четырьмя сторонами 500 должен давать 25 м² и периметр 20 м;
- undo/redo;
- диагонали auto/manual/edit/delete;
- цифры: перенос, поворот 360°, изменение размера, сохранение позиции/угла/размера;
- touch-контракт режима Стена и правую полосу 74 px;
- Saved measurements: свайп по карточкам, поиск, нижняя навигация не перекрывает список;
- закупочный и клиентский расчёт, пользовательские материалы, дюбель 6 шт/м;
- JSON export/import;
- PDF: файл реально создан, размер > 0, первые байты `%PDF-`;
- настройки интерфейса/ночной режим и их сохранение.

Тесты нельзя удалять, ослаблять, помечать skip или заменять ручным утверждением «должно работать». Если что-то невозможно проверить автоматически, явно напиши UNVERIFIED и НЕ называй сборку готовой.

ПРОВЕРКА ПОСЛЕ СБОРКИ
После APK распакуй/проинспектируй его и докажи, что `assets/index.html` имеет тот же SHA-256 golden master. Проверь, что manifest не просит ненужных опасных разрешений и что приложение не требует интернет для основной работы.

КРИТЕРИЙ ГОТОВНОСТИ
Работа считается завершённой только если:
- golden HTML не изменён ни на байт;
- все mandatory checks зелёные;
- APK успешно собран GitHub Actions;
- APK artifact доступен;
- список функций из FEATURE_CONTRACT отмечен PASS с указанием теста/доказательства;
- нет uncaught JavaScript errors;
- нет пропавших функций и визуальных регрессий.

В ФИНАЛЕ ДАЙ ТОЛЬКО ПРОВЕРЯЕМЫЙ ОТЧЁТ:
1. commit SHA;
2. ссылка/название workflow run;
