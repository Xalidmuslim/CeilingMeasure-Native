# ГрузШер КБР — рабочая SMS-авторизация / подготовка KYC

**Состояние: интеграционный фундамент, ещё не запущенный коммерческий сервис.**

Сервер реализует SMS-авторизацию, защиту одноразовых кодов, выпуск сессий и серверный допуск к аренде. Проверка паспортов и водительских прав намеренно заблокирована до подключения официального провайдера.

## Архитектура
- Android: отдельный экран «Рабочая регистрация», не смешан с демонстрационной заявкой. **Нет загрузки реальных паспортов в демо.**
- Сервер: FastAPI + PostgreSQL в российском дата-центре, только HTTPS.
- SMS: SMS Aero `/v2/sms/send` с ключом, хранящимся исключительно на сервере.
- KYC: `POST /v1/driver-verifications/start` возвращает **503 KYC_PROVIDER_NOT_CONFIGURED**, пока не заключён договор и не добавлен доверенный механизм проверки подлинности паспорта, водительского удостоверения, категории, срока действия и соответствия владельцу.
- Аренда: `/v1/bookings/eligibility` запрещает выдачу реальной машины всем непроверенным водителям, даже после успешного входа по SMS.

## Настройка
Создайте PostgreSQL (в РФ), секреты через переменные окружения, TLS и домен на HTTPS, затем запустите:
```bash
export APP_ENV=production
export DATABASE_URL='postgresql+psycopg://<user>:<password>@127.0.0.1:5432/gruzsher'
export APP_SECRET='<случайная строка от 32 символов, хранить только на сервере>'
export SMSAERO_LOGIN='<логин>'
export SMSAERO_API_KEY='<ключ>'
export SMSAERO_SIGN='<согласованное имя отправителя>'
pip install -r requirements.txt
uvicorn server:app --host 127.0.0.1 --port 8080
```
В реальном развёртывании используйте менеджер секретов, HTTPS reverse proxy, ограничения исходящего трафика, резервные копии БД, контроль логов и PostgreSQL с правами минимально необходимого доступа. Не копируйте эти значения в GitHub или APK.

Android API URL собирается только из `GRUZSHER_REAL_API_URL=https://api.example.ru` (реальный собственный сервер) при сборке Android. Без URL мобильный экран явно пишет, что сервер не подключён, и не позволяет вводить реальные данные в демоверсию.

## Договоры и юридические условия до реального запуска
1. Подтверждение статуса оператора персональных данных, локализация данных граждан РФ на территории РФ согласно 152-ФЗ, политика, основания обработки, сроки удаления и документация по безопасности; проверить требования уведомления Роскомнадзора.
2. Договор с SMS-провайдером; реальный домен HTTPS; российская БД.
3. Договор и верифицированная интеграция с провайдером идентификации/антифрода (например Smart ID Engine в собственном контуре), независимая оценка действительности ВУ, категории и лица; тестировать без реальных персональных данных до прохождения процедур.
4. Согласия и необходимые основания для обработки. Биометрическая идентификация и селфи могут создавать специальные дополнительные требования; не включайте их без юридической проверки.
5. На продакшне использовать миграции схемы БД, повышенные лимиты защита от спама на уровне nginx/WAF, аудит операций и контроль злоупотреблений. **Реальный доступ к замкам автомобилей здесь отсутствует.**
